# Sentinel 重构计划

状态：设计草案，2026-10-27。本文是迭代计划，不代表计划中的监控能力已经实现。

## 产品目标

将当前网络探测看板演进为面向基础设施、网络、数据库、中间件和云原生资源的轻量运维监控工作台。每一项展示都必须对应配置过的目标和真实采样，缺少证据时显示未知或不可用。

当前仅有 ICMP、TCP、TLS、HTTP 四种探测以及调度、告警、趋势、证书和维护窗口；`domain` 是分类字段，不代表相应域已具备采集能力。断言层在 PR #6 中，尚未合入 main。

## 参考与适用边界

| 参考 | 借鉴 | 不直接承诺 |
|---|---|---|
| [Uptime Kuma](https://github.com/louislam/uptime-kuma) | 监控项配置、状态时间线、通知与维护窗口工作流 | 不复制其代码、品牌或承诺同等功能 |
| [Prometheus blackbox exporter](https://github.com/prometheus/blackbox_exporter) | 黑盒探测与结果证据分离、模块化监测协议 | 不默认部署 exporter 或进行资产发现 |
| [Prometheus node exporter](https://github.com/prometheus/node_exporter) | 主机指标和采集器边界 | 不假设能采集远程 Windows 主机 |
| [PostgreSQL exporter](https://github.com/prometheus-community/postgres_exporter) / [Redis exporter](https://github.com/oliver006/redis_exporter) | 数据库指标、权限与版本适配 | 不自称已完成数据库接入 |
| [kube-state-metrics](https://github.com/kubernetes/kube-state-metrics) | Kubernetes 对象状态与资源指标分开建模 | 不默认访问集群或自动发现 |
| [Grafana Alloy](https://grafana.com/docs/alloy/latest/collect/prometheus-metrics/) | 可选采集/指标源与界面解耦 | 不强制引入采集器或托管服务 |

项目借鉴产品与架构思路；若未来引入代码或第三方组件，需单独核查版本、许可证、权限和供应链，再决定是否采用。

## 产品结构

1. **总览**：异常、未知、维护状态、最近事件和采集器状态；筛选后钻取，不用无来源的综合评分替代证据。
2. **监控对象**：按基础设施 / 网络 / 数据库 / 中间件 / 云原生分组，显示类型、目标、状态、最近采样、证据与操作。
3. **接入向导**：按类型给出必填参数、认证来源、目标授权提示、超时和连接测试；仅对用户配置的目标执行。
4. **详情**：展示可用率、时间线、原始观测值、阈值、最近错误和数据新鲜度；空、未知、部分失败等状态显式呈现。
5. **事件与告警**：状态变化、维护窗口、通知投递与失败原因；不将未知当作恢复。
6. **设置**：采集周期、历史留存、凭据引用、数据源与运行状态。已有配置兼容迁移并可回滚。

## 实施顺序与验收

### 0. 可信基线

- 修复关闭时运行中的采样/请求可能晚于锁释放的问题；定义超时、退出和进程锁持有语义，覆盖慢检查与并发关闭。
- 已在重构分支修复 `/readyz` 未验证存储可写的问题；覆盖写入失败与恢复。目录探测不能保证后续写入一定成功或磁盘持久性。
- 审核 PR #6 的断言语义、兼容性与历史体积；CI 和实际启动检查通过后再决定其合并路径。

### 1. 设计令牌与应用壳层

- 先定义色彩、排版、间距、状态、焦点、响应式和组件契约，再构建导航、工作区和全局状态；保留现有 API 的真实数据接入。
- 交付可操作的总览、列表和详情首个垂直切片；加载、空、异常、未知、断连、重试状态均可见。
- 验收桌面与移动布局、键盘与可见焦点、真实 API 和现有功能回归。样例数据只能在明确标记的隔离演示模式使用。

### 2. 资产与配置

- 设计资产、监控项、采样、事件和数据源的兼容模型，提供配置预览、校验、保存与错误提示；原配置可导入且可回滚。
- 写接口上线前确定本地访问、来源校验、敏感信息、授权范围及文件原子写入策略。单实例及资源上限不因重构而静默放宽。

### 3. 基础设施与网络

- 已在重构分支增加本机路径磁盘容量采集；受控 DNS 和其余主机指标仍待实现。主机能力从标准库开始，跨平台差异明确显示。
- 可选支持明确配置的 exporter 数据源；限制目标、超时、响应大小、指标数量及标签基数。
- 本地替身覆盖成功、超时、畸形响应和不可用；结果、历史与页面证据贯通。

### 4. 数据库与中间件

- 先交付一个低风险垂直切片（例如 Redis 只读健康/有限指标），再按实际需求扩展 PostgreSQL、MySQL、Nginx 等。
- 优先评估已有 exporter 的只读接入；直接协议实现须限定命令、权限、认证、超时和版本兼容，禁止任意 SQL 或业务数据读取。
- 以本地可控替身验证正常、认证失败、超时、兼容和权限不足；不依赖真实公网资产。

### 5. 云原生

- 在数据源认证与授权基础具备后，先支持明确配置的只读 Kubernetes 指标源或 API，展示节点与工作负载状态。
- 限定 RBAC、命名空间、对象与响应数量；不启用自动发现或 exec/logs/写操作。提供缺凭据、权限不足、过期数据和离线状态。

### 6. 质量与发布

- 每阶段更新测试与文档，覆盖数据来源、超时和资源上限、错误路径、可访问性及响应式布局。
- 在独立分支提交、通过相关测试与 CI 后创建可审查 PR；不自动合并、发布或部署。

## 决策点

- 标准库、无外部数据库继续作为当前基线；是否引入数据库驱动、Prometheus 查询或其他依赖，须在具体切片中以维护成本、许可证和功能收益验证，不能把规划当作已选型。
- 现有 JSONL 的体积与读取限制适合轻量场景；需要高基数和长周期分析时，先比较 SQLite 与可选外部时序数据源，不把现有历史伪装成完整时序数据库。
- 开放网络访问或接收凭据前，先完成访问控制、最小权限和敏感数据处理设计；本机默认绑定行为保持明确。
